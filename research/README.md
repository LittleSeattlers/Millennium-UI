# Research frontier

`frontier.v1.json` is the human-curated starting graph for bounded Millennium work. It is deliberately a frontier, not a claim that the listed branches exhaust the mathematics.

Each task has a stable ID, problem and theorem direction, branch, task kind, bounded objective, useful-success and useful-failure conditions, a verification method, an editorial planned budget, and a priority. The runner derives a visible value contract from those fields: a useful positive result, a useful negative result, required evidence, a novelty comparison, and the publication floor. The 30- and 45-minute values are human-authored scopes, not measured runtime predictions. Every merged contribution records its selected task ID, but only a locally accepted or explicitly trusted record can mark a task attempted, satisfy a prerequisite, supply prior prose, create successor tasks, or enter the verification queue. A completed run withheld by the value gate leaves the task open.

When no genuine non-review task fits the safe allowance, the runner may derive a deterministic 15-minute preparatory slice from an available oversized task. The slice has its own stable `auto.slice.v1.*` ID, inherits the parent's branch and prerequisites, and must produce a dependency map, one falsifiable subclaim, one concrete check, and child proposals—or an exact reason that sound subdivision is not yet possible. Completing the slice never completes, truncates, or weakens the parent task. Below 15 safe minutes, no research mode—including a contributor-proposed exploration—can start: two minutes are reserved for durable finalization, and the remaining work window is too small for the minimum useful contract.

The dashboard's single Automatic run mode chooses the best-fitting unclaimed frontier task, uses the Standard policy (a fixed 10% quota reserve with the existing conservative burn-rate margin), and selects the strongest suitable account model. Every eligible run receives High reasoning when the selected model supports it; Extra high is reserved for verification with ample headroom. Frontier path, quota reserve, and model/reasoning overrides remain together under Advanced settings. The concrete policy selected at launch stays fixed for the entire attempt and for every runtime quota guard.

The runner supports four selection modes:

- **Recommended** chooses a currently available task using editorial priority, fit to the safe time allowance, independent-verification value, linked prior context, and the number of waiting tasks it can unlock.
- **Browse frontier** lets the contributor choose any available curated branch.
- **Explore new direction** creates a stable branch ID from a contributor-supplied direction. It is not limited to this catalog.
- **Verify result** creates a linked, still-unreviewed review attempt for a trusted completed record without sending its research prose to the hosted browser.

The provider must leave `CONTRIBUTION.proposed.json` with a value assessment, at least one scoped claim, and zero to three possible successor tasks. The value assessment explicitly records outcome type, novelty against prior work, evidence, and a falsifier. The connector publishes only records that also contain a limitation and a concrete next action or successor. After a normal reviewed commit adds the source attempt ID to `trusted-contributions.v1.json`, deterministic stable IDs can turn those proposals into frontier tasks; child tasks depend on a completed parent, alternatives form another branch, and verification proposals enter the review queue. A verification record stays unreviewed and linked—it does not automatically promote a mathematical claim.

Local leases remain under the gitignored `.millennium/private/` directory. Cross-machine claims are draft pull requests with machine-readable task IDs and expiration times. A connector rechecks claims immediately before starting; if simultaneous claims race, the lowest pull-request number wins. This is best-effort coordination rather than a perfectly atomic distributed lock, but it works without a maintained server and prevents the ordinary duplicate-start case.
